# Quickstart

Get a base URL and an API key, send one request, and see it in Usage. On
otari.ai that takes about five minutes; running Otari yourself with Docker
Compose takes a few more.

## 1. Get a base URL and an API key

{% tabs %}
{% tab title="otari.ai" %}
You need an [otari.ai](https://otari.ai) account. Your default workspace is
enough for a first request.

1. Sign in and open your default workspace in the top-left corner.
2. Open the **API Keys** tab and click **Create key**. Name it and copy the key,
   which starts with `otk_`. It is shown only once.
3. Open the **Models** tab and pick a model. **Use this model** shows its
   selector.

```bash
export OTARI_BASE_URL=https://api.otari.ai/api   # https://eu.api.otari.ai/api for an EU account
export OTARI_API_KEY=otk_...
export MODEL=deepseek/deepseek-v4-pro-0813
```
{% endtab %}

{% tab title="Self-hosted" %}
This runs a persistent standalone Otari with Docker Compose. For an ephemeral,
no-clone example, use the [README quickstart](../../README.md#quickstart).

You need Docker with Compose and a provider API key.

#### Configure

```bash
git clone https://github.com/mozilla-ai/otari
cd otari
cp config.example.yml config.yml
```

Edit `config.yml` to set a master key, provider, and pricing:

```yaml
database_url: "postgresql://otari:otari@postgres:5432/otari"
master_key: "choose-a-strong-management-key"
default_pricing: true

providers:
  openai:
    api_key: "sk-..."
```

This local file is gitignored. For a shared deployment, inject secrets through
the environment or your platform's secret manager instead.

`default_pricing: true` uses bundled prices for common models. Without it,
add explicit pricing for the model you call. Otari rejects unpriced budgeted
traffic by default.

To store provider credentials through the dashboard instead, leave
`providers` empty and set `OTARI_SECRET_KEY` to a Fernet key generated by
`otari gen-secret-key`.

#### Start

```bash
# Provider copies of attached files need a pepper of their own. Compose reads .env.
grep -qs OTARI_PROVIDER_ACCOUNT_PEPPER .env || echo "OTARI_PROVIDER_ACCOUNT_PEPPER=$(openssl rand -base64 32)" >> .env
docker compose pull
docker compose up -d
curl http://localhost:8000/api/v1/health
```

Otari refuses to start without `OTARI_PROVIDER_ACCOUNT_PEPPER` while provider
copies are on, which they are by default. See
[Provider copies](../reference/configuration.md#provider-copies).

The first startup on an empty database creates an API key and prints it once.
Find the `tk-` value in the Otari container logs. You can also create a key
from the dashboard at `http://localhost:8000/`.

```bash
export OTARI_BASE_URL=http://localhost:8000/api
export OTARI_API_KEY=tk-...
export MODEL=openai:gpt-4o-mini
```
{% endtab %}
{% endtabs %}

Keep the key in your shell or a secret store, never in source control.

## 2. Send a request

```bash
curl "$OTARI_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $OTARI_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"$MODEL\",
    \"messages\": [{\"role\": \"user\", \"content\": \"Say hello.\"}]
  }"
```

The request is authenticated, checked against applicable budgets, routed with
the provider credential Otari holds, and recorded.

## 3. Confirm it worked

Open the workspace's **Usage** tab and find the request. If it is not there,
check the base URL first ([Connect to Otari](connect.md)), then the API key.
